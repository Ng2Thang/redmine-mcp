## Detailed Redmine MCP usage guide

1. **Choose a project.** Ask which Redmine projects are visible. MCP returns project names and IDs. Confirm the destination before reading or writing data. Example: Demo API has project ID 2.

2. **List and filter issues.** Example requests include listing issues in Demo API, open issues, issues assigned to the current user, or issues updated since a date. Filters include project, status, assignee ("me"), tracker, version, category, parent issue, and update time. Results are paginated. Totals cover only issues visible to the current user and may exclude restricted data.

3. **Read an issue.** After obtaining its ID, request its details. The response may include title, description, project, status, priority, author and assignee, dates, logged time, notes, and attachment metadata. Attachment contents are not downloaded automatically.

4. **Create an issue.** Specify the project, title, and description. Optional fields include tracker, status, priority, assignee, start and due dates, and parent issue. Save the returned issue ID and check the result. Creation requires an enabled MCP writer connection and the Redmine Add issues permission. A role name such as Manager does not prove that permission is granted.

5. **Update an issue or add a note.** Specify the issue ID and exact field or note to change. Notes require Add notes permission. Other fields require their corresponding Redmine permissions and may be restricted by workflow. A notes-only update does not require Edit issues according to the tool contract, but still requires Add notes.

6. **Check permissions and results.** MCP returns only projects, issues, and data visible to the current account. Memberships do not establish every effective permission. Write tools require a separate enabled writer deployment and the matching Redmine permission. A "matched" result means the supplied data matched on read-back. If a write result is uncertain, inspect the issue or journal before retrying to avoid duplicates.

**Example workflow:** list projects → choose Demo API → list open issues → select an ID → read the issue → request a specific update or note → check the read-back result.

## Redmine MCP activity flow

1. The user sends a natural-language request through an MCP client.
2. Redmine MCP selects the appropriate tool, validates the input, and calls the API.
3. The request reaches the Redmine REST API using the connection credentials.
4. Redmine applies access permissions, roles, and workflow rules, then returns the result through MCP.

**Reading data:** projects and issues can be listed and viewed within the current account's visibility.

**Writing data:** creating or updating issues, adding notes, or attaching files requires an enabled writer connection and the corresponding Redmine permission, such as Add issues or Add notes.
